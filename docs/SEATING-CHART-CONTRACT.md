# The seating chart — what the engine needs from the utterance model

**Orville, 2026-08-02, under Howell's W-21 ruling** (*"settle W-21 properly"*),
his two bench rulings of today (recorded in the ledger, O-17), and **checked
against every shape in W-30** — this document answers Wilbur's closing line,
*"tell me what the data must provide and I will provide it."* It is the
engine↔data contract for the utterance model in the wheel: **what the data
must provide**, not how it is authored or stored. The chapter files and their
spans remain Wilbur's per `docs/VERSIFICATION-MODEL.md`; this artifact is
*generated* from them, the way `catalog-lite.json` is generated from the
catalog. If generating it surfaces a shape neither of us has named, that is a
ledger conversation, not a silent convention.

## Why a generated artifact

The wheel builds its verse chain **synchronously at boot** from the manifest.
It cannot open 1,215 chapter files to learn which seats exist, and after the
utterance model those files are the only place the truth lives. The seating
chart is that truth, flattened per served edition into exactly the shape the
chain needs, regenerated by cargo tooling whenever the corpus changes.

The engine never pivots edition-to-edition through numbers. Every query goes
through **spine coordinates**, and this design does not inherit the known
lossy edge of KJV-pivot systems (SWORD/av11n): **our spine is a constructed
superset** — every utterance any tradition attests has a spine identity — not
an English tradition drafted into service as a hub.

## The artifact

One file per **served artifact**: `data/gutenberg/seating/<CODE>.json`
(deployed and gzipped like every other data file; regenerated, never
hand-edited). *Served artifact*, not raw edition: where one edition composes
over another (THEOD over LXX — the whole Greek Bible with Daniel in
Theodotion's voice), the generator resolves the composition and the engine
receives one chart for the one artifact the reader can choose.

```jsonc
{
  "_generated_from": "<cargo data version>",   // staleness check
  "edition": "WLC",
  "books": {
    "GENE": [
      31,                     // ch 1: IDENTITY — 31 seats, labels "1".."31",
                              //   utterances 1..31 of the spine's 1st chapter
      25,                     // ch 2: identity again
      // …
      { "s": [                // ch 50: a SEAM — explicit seats, in order
        { "l": "1",  "u": ["50", 1, 1] },
        // …
        { "l": "22", "u": ["50", 22, 23] },   // one seat spanning u22–u23
        { "l": "23", "u": ["50", 24, 24] }
        // …
      ]}
    ],
    "MALA": [
      14,
      17,
      { "c": "3", "s": [      // Hebrew Malachi 3 has 24 seats; the last six
        // …                  // draw their utterances from the spine's ch 4
        { "l": "19", "u": ["4", 1, 1] },
        { "l": "24", "u": ["4", 6, 6] }
      ]}
      // and NO fourth chapter: membership is the edition's own
    ],
    "IUDITH": { "convention": true, "chapters": [ /* … */ ] }
  }
}
```

### Semantics

- **A book is an ordered array of the edition's own chapters** (or, when it
  needs a book-level flag, an object `{ "convention": …, "chapters": […] }`).
  The edition's chapter count may differ from the spine's — Hebrew Malachi
  has three entries; a book absent from the artifact is absent from `books`.
- **An integer chapter is the identity default**: it IS the spine chapter at
  the same position in the spine's own chapter sequence — N seats, labels
  `"1"`…`"N"`, utterance k ↔ seat k — and it inherits that spine chapter's
  display identity from the manifest. This is positional against the spine's
  *sequence*, not its numeric ids, so ECCLU's chapter 0 (the Prologue, whose
  name is Πρόλογος and renders as a name, not a number) costs nothing: it is
  simply the sequence's first entry. The 1:1 majority of the corpus stays
  this cheap.
- **An explicit chapter is `{ "c"?, "convention"?, "s": [seats…] }`.**
  `c` is the edition's own chapter label, when its grouping departs from the
  spine's (Hebrew Malachi's `"3"`); omitted, the chapter keeps the
  same-position spine identity. Each seat:
  - `l` — the display label, the edition's own verse name exactly as its
    reckoning writes it (`"19"`, `"12a"`, `"19d"` — W-30's source-side letter
    axis). Unique within its chapter.
  - `u` — the utterance span in spine coordinates: one
    `[spineChapterKey, firstOrdinal, lastOrdinal]` triple, or — for the 11
    many-to-one folds, which are **not contiguous** (LXX ECCLU 31:32 and
    31:35 → 34:27) — an array of such triples in spine order. Ordinals index
    the spine chapter's `utterances` list, so spine-side sub-slots (`15b`,
    W-30's other letter axis) are just ordinals here; the slot-id ↔ ordinal
    correspondence lives in the chapter file and never enters the chart.
- **Seats appear in the edition's reading order**, which must equal spine
  order of their first utterance. The chain, the gaps and the parent labels
  are all built from this order; the cousin-gap grammar breaks at the
  edition's OWN chapter boundaries (the entire point of W-18/O-13).
- **A span may draw from a foreign spine chapter** (Malachi 3's tail,
  Psalm 9/10, all 1,434 cross-chapter entries) but a single range may not
  cross spine chapter files in v1. If a real case ever needs it, flag it —
  do not invent a convention silently.
- **An asserted absence is the absence of a seat.** The 821 verses an
  edition demonstrably never held get no entry; the edition's own labels
  carry the evidence (LXX 1 Samuel 17 runs …11, 32… and the numbering
  itself shows the gap — honest, and no asterisk). The reader is never shown
  filler, and foreclosure does the rest: a language is simply not offered at
  an utterance no servable edition of it holds.
- **`convention: true`** — on a book (IUDITH, TOBI) or an explicit chapter
  (the Exodus tabernacle chapters) — declares W-30's warning #1: editions
  share these coordinates **by convention only**; utterance identity does
  not hold across editions here (two recensions, unrelated text at the same
  address). The engine still lands by coordinate when switching — there is
  nothing better to land by — but it must never stage the versification
  choreography there, because the re-seat animation asserts "same words,
  different seat," and that assertion would be false.

### Invariants the generator must enforce (and cargo CI should test)

1. **The spine is a superset** — every `u` names utterances that exist.
2. **No utterance is claimed twice by one artifact** (mirrors the schema's
   span rule; the chart inherits it).
3. **Ordering**: seats ascend by first utterance in spine order; chapters
   ascend likewise; fold ranges are listed in spine order.
4. **Label uniqueness** within each edition-chapter.
5. **Text agreement**: every seat has text for this artifact at that
   (edition, address) in the corpus; every text the artifact holds has a
   seat; and every spine utterance the artifact neither seats nor asserts
   absent is a **generation failure**, not a silent gap. Asserted absence
   and drift must be indistinguishable to the reader but never to CI.

### What the engine does with it

- **Membership & labels**: the verse chain for the active artifact is read
  straight off the chart — retiring `verse_count` as the chain's source, and
  with it the phantom-seat/hidden-verse class (110 + 110 today).
- **Text fetch**: seat → spine chapter file (via the manifest) → the
  edition's string at the seat's own address. Unchanged storage; per W-30 a
  span's text lives whole at its first slot and is never cut.
- **Rotation (the Malachi demonstration)**: reader's position = utterance =
  (spine chapter, ordinal); target seat = the seat in the target artifact's
  chart whose span covers it. Spine→seat is single-valued (the folds are
  many-to-one, never one-to-many), so landing is deterministic. Per Howell's
  rulings today: the landing seat shows its **whole** verse, uncut; a fusion
  is **legible as an event** in the re-seat choreography and invisible at
  rest — except under `convention: true`, where no correspondence exists and
  none is performed.
- **Foreclosure**: a language is offered at a leaf iff some servable
  artifact of it has a seat spanning the reader's utterance — read from the
  charts, lazily loaded (identity compresses to integers; they are small).

### Fallback, stated so nobody is surprised

Until an artifact's chart exists, the engine derives an identity chart from
manifest `verse_count` — i.e. exactly today's behaviour, phantom bug
included. Charts land, the bug dies; data first, engine tolerant, as always.

## Not in this contract

Where spans are authored (Wilbur's chapter files, spine-resident — settled),
the schema rules (his step 1), TVTMS or any authoring witness (evidence for
his step 2, never a runtime dependency), the note-only books' prose (detail
sector, unchanged), and the session-memory format — which needs no
*format* migration: the saved position is a spine address, the chapter file's
`utterances` list converts address ↔ ordinal on recall, and the chart takes
it from there.
